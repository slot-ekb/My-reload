========================================================================
 sweep — сколько ПОТОКОВ (nthreads) лучше в ОДНОМ солвере
========================================================================
Отдельный самодостаточный стенд (фейк-нода + прокси + майнер). Боевое
(/opt/proxycpu1, /opt/proxygpu1) и testgc НЕ трогает — свои порты 3699/3600.

  ./sweep.sh [секунд] ["список потоков"] [бинарь]
  ./sweep.sh                       # 40с, потоки "1 2 4 6 8", orig
  ./sweep.sh 60 "1 2 3 4"          # свой список
  ./stop.sh                        # погасить, если прервал

Что делает: для каждого N из списка гоняет
  (A) 1 солвер × N потоков  на N физ.ядрах
  (B) N солверов × 1 поток   на тех же N ядрах   (COMPARE=on)
и печатает таблицу g/s и ШАР/С.

Читать по ШАР/С:
  - Правый столбец (B) — независимые солверы, обычно растёт линейнее.
  - Левый (A) — потоки внутри одного солвера, масштабируются хуже
    (cuckatoo упирается в память). Где A перестал расти — потолок nthreads.
  Вывод: на одном CPU почти всегда выгоднее МНОГО солверов по 1 потоку,
  чем один «толстый» солвер. sweep показывает это на ТВОём железе.

config.env: BIN, SECS, THREADS, COMPARE, порты.
